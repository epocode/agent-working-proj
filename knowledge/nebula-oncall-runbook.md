# Nebula 值班与事故响应 Runbook

## 告警分级

| 级别 | 定义 | 示例 |
| --- | --- | --- |
| **P0** | 核心链路不可用或资损 | 登录失败率 > 20%，计费错误 |
| **P1** | 主要功能受损，有绕行方案 | 单个区域 API 5xx > 5% |
| **P2** | 非核心功能异常 | 报表延迟、通知丢失 |
| **P3** | 体验问题或咨询 | 页面样式错位 |

## 响应时限

- **P0**：5 分钟内响应，15 分钟内拉起 incident 频道，1 小时内给出首个对外说明。
- **P1**：15 分钟内响应，30 分钟内定位。
- **P2**：4 小时内响应，次工作日处理。
- **P3**：下个迭代排期。

## 升级路径

1. 值班工程师（on-call）先确认告警，判断级别。
2. P0/P1 立即升级给 **SRE Lead**，并通知 **Service Owner**。
3. 涉及计费、鉴权、数据安全，同步通知 **平台负责人** 和 **安全值班**。
4. 超过 30 分钟未定位，升级到 **技术负责人**。

## 事故沟通

- P0/P1 每 **30 分钟** 在 incident 频道同步一次进展，格式：现状 / 影响 / 正在做什么 / 下次同步时间。
- 对外沟通由 PR 统一出口，工程师不要在客户群直接回复。
- 事故频道命名：`#inc-<YYYYMMDD>-<简短描述>`。

## 复盘要求

- P0 和 P1 必须在 **72 小时内** 完成复盘文档。
- 复盘必须包含：时间线、根因、影响面、处置过程、改进项（含 owner 和截止时间）。
- 改进项要进 Jira 跟踪，两周后检查完成率。

## 值班交接

- 每周一 10:00 交接，交接内容包括：未闭环告警、进行中的变更、已知风险。
- 值班期间手机保持可联系，P0 电话 5 分钟未接会自动升级。

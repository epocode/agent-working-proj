# Nebula 平台概览

> 本文档是 demo 用的虚构内部资料，用来演示本地知识库检索（BM25）。

## 一句话定位

Nebula 是面向研发团队的内部「服务健康度」平台：把服务目录、指标告警、发布编排放在一个控制台里，
目标是把「服务出问题后到处找信息」变成「一个页面看到全部上下文」。

## 核心模块

- **Orbit（服务目录）**：登记服务、负责人、依赖关系、SLO。每个服务有唯一的 `service_id`，格式为 `svc_<小写字母数字>`。
- **Pulse（指标与告警）**：采集 RED 指标（Rate / Errors / Duration），按服务聚合，支持告警分级。
- **Comet（发布编排）**：编排灰度发布、审批、回滚，和 CI 流水线通过 webhook 对接。
- **Nova（知识库）**：内部文档与 runbook 的检索入口。本 demo 的 `kb` MCP 服务器就是它的简化版。

## 版本代号

Nebula 的版本代号按季度轮换，统一使用天文学名词：

| 季度 | 代号 |
| --- | --- |
| 2026 Q4 | Aurora |
| 2027 Q1 | Borealis |
| 2027 Q2 | Cassiopeia |
| 2027 Q3 | Draco |

对外沟通和发布说明里必须使用代号，不要只写版本号。当前主力版本是 **Aurora**。

## 角色

- **Service Owner**：对服务可用性负责，审批本服务的发布。
- **SRE**：审批高风险发布，负责值班和事故升级。
- **Release Captain**：每个发布窗口的协调人，由 SRE 轮值。

## 技术栈约定

- 后端服务默认 Go 1.23；前端使用 TypeScript + React。
- 所有对外 API 必须走统一网关，不允许服务直连公网。
- 新服务接入 Nebula 时必须在 Orbit 注册，并提供至少一条 SLO。
